# Argon x86-64 Linux ABI

Argon follows the System V AMD64 ABI on x86-64 Linux. This document fixes the
subset relied on by generated programs and the native runtime so that bootstrap
and self-hosted compilers remain interoperable.

## Calls and returns

- Integer, boolean, object, array, and string values occupy one eight-byte
  argument slot. Narrow integers are normalized to their declared width.
- The first six argument slots use `rdi`, `rsi`, `rdx`, `rcx`, `r8`, and `r9`.
- Remaining slots are placed on the stack from right to left. The caller removes
  them after the call.
- `rsp` is aligned to 16 bytes immediately before every `call` instruction.
- Integer-like and reference results are returned in `rax`. `void` has no result.
- `rbx`, `rbp`, and `r12` through `r15` are callee-saved. All other general
  registers are caller-saved. `r11` is reserved as dispatch scratch at indirect
  call sites.
- The direction flag is clear at public function boundaries.

Constructors and instance methods receive `self` as argument slot zero. This
means five explicit arguments remain in registers before stack passing begins.
Direct, virtual, and contract calls use the same argument representation.
Dispatch must resolve an indirect target before loading the final argument
registers, or preserve every argument register it uses as scratch.

## Stack frames and garbage-collection roots

Generated functions establish an `rbp` frame and reserve a 16-byte-aligned local
area. Parameters and IR temporaries use eight-byte frame slots. Parameters after
the sixth slot are read beginning at `[rbp+16]`.

Each generated frame links a root record into `argon_gc_roots`. Every return path
must restore the previous root record before restoring the frame and returning.
Runtime helpers that call other functions must obey the same stack-alignment and
callee-saved-register rules even when they are only called by generated Argon.

## Runtime and process boundary

Generated executables expose the platform `main(i32 argc, u8** argv)` boundary.
The runtime records process arguments before constructing the entry object.
`entry.__` may return an integer process status; a `void` entry returns zero.

Native `System` methods use the same register and stack convention as generated
methods. Their assembly symbols are prefixed with `argon_System_`. Compiler-owned
helpers use the `argon_` prefix. Both prefixes are reserved and user symbols are
mangled so they cannot collide with runtime labels.

The current ABI covers integer-like and managed-reference values only. Floating
point register classes, aggregate-by-value passing, exception unwinding, dynamic
libraries, and a stable foreign ABI are explicitly deferred to their roadmap
items.
